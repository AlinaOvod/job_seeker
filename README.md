# Job Alert Bot

Telegram-бот, який кожні ~15 хвилин перевіряє джерела вакансій і надсилає в чат нові, що підходять під твої критерії. У повідомленні назва, джерело, (за можливості) компанія та місто, і кнопка **«Відгукнутися»**, яка відкриває вакансію на сайті.

Працює безкоштовно на GitHub Actions: жодних серверів. Уже надіслані вакансії запам'ятовуються у файлі `state/seen.json`, який бот сам комітить у репозиторій. Одна й та сама вакансія, знайдена в кількох джерелах, приходить один раз.

## Звідки бот бере вакансії

| Джерело | Спосіб | Швидкість | Статус |
|---|---|---|---|
| **Djinni** | RSS `djinni.co/jobs/rss/` | майже одразу | Перевірено: стрічка існує. Вона загальна (всі категорії), тому фільтри за назвою працюють на боці бота |
| **DOU** | RSS по категоріях | майже одразу | ⚠️ Адресу категорійних стрічок не вдалося перевірити (дивись нижче) |
| **LinkedIn** | листи-алерти через пошту | **раз на день** | LinkedIn дозволяє лише Daily/Weekly, миттєвих листів немає |
| **Work.ua, Robota.ua, jobs.ua** | листи-алерти через пошту | залежить від сайту | Шаблони посилань підготовлені, але на реальних листах не перевірені |
| **Telegram-канали** | веб-версія `t.me/s/канал` | кілька хвилин | Потрібні назви каналів, які ти читаєш |

LinkedIn і сайти без RSS бот читає **лише через листи, які самі сайти надсилають тобі**. Скрапінг цих сайтів порушує їхні правила і швидко ламається, тому я його не роблю.

### Що з цього відповідає на «хто перший відгукнувся»
Для швидкості найкращі Djinni, DOU і Telegram-канали: вони дають вакансію за хвилини. Листи LinkedIn це денний дайджест, тому там перевагу «першою» не отримати, але ти нічого не пропустиш.

⚠️ Стрічка Djinni віддає лише останні ~18 вакансій (приблизно 40 хвилин). Якщо GitHub Actions запуститься із запізненням більше ніж на цей час, частина вакансій може не потрапити в бот.

## Запуск (≈10 хвилин)

### 1. Створи бота
1. У Telegram відкрий **@BotFather** → `/newbot` → вигадай ім'я.
2. Збережи **токен** (вигляду `123456:ABC...`). Нікому його не показуй.
3. Відкрий свого бота і натисни **Start**.

### 2. Дізнайся свій chat id
Відкрий у браузері (підстав свій токен):

```
https://api.telegram.org/bot<ТОКЕН>/getUpdates
```

Знайди `"chat":{"id":123456789,...}`. Це число і є `TELEGRAM_CHAT_ID`. Якщо відповідь порожня, напиши боту будь-яке повідомлення і онови сторінку.

### 3. Репозиторій на GitHub
1. Створи **публічний** репозиторій і завантаж туди цю папку.
   Чому публічний: у приватному безкоштовно лише 2000 хвилин Actions на місяць, а запуск кожні 15 хвилин забирає ~2900. У публічному ліміту немає. Секретів у коді немає (токени лежать у Secrets). Публічними будуть лише фільтри та посилання на вакансії, які бот уже бачив.
   Якщо хочеш приватний, зміни в `.github/workflows/check.yml` розклад на `*/30 * * * *`.
2. **Settings → Secrets and variables → Actions → New repository secret**, додай:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
3. Вкладка **Actions** → увімкни workflows → **Check vacancies → Run workflow**.

Перший запуск лише запам'ятовує вакансії, що вже є, і пише «Бот запущено». Далі приходитимуть тільки нові. (Так само поводиться кожне нове джерело, яке ти додаси пізніше.)

## Сайти вакансій конкретних компаній

Вакансії на власному сайті компанії часто з'являються раніше, ніж на DOU чи Djinni. Є три способи їх читати, від надійного до крихкого:

| Тип у `config.json` | Для чого | Надійність |
|---|---|---|
| `ats` | Компанія тримає вакансії в Greenhouse, Lever, Ashby, Workable або SmartRecruiters. Це публічні API з готовим JSON | Висока |
| `html` | Список вакансій є прямо в HTML сторінки (напр. SoftServe) | Середня: ламається, якщо сайт змінить верстку |
| не підтримано | Сайт підвантажує список скриптом із власного закритого API (типово для великих компаній, напр. EPAM, Workday-сайти) | Бот такі не читає |

**Як дізнатися, що саме в компанії.** Запусти на своєму комп'ютері (потрібен Node 20+ і `npm install`):

```bash
npm run detect -- https://careers.example.com/ https://jobs.other.com/
```

Утиліта відкриє сторінку, знайде сліди відомих систем найму і для підтримуваних надрукує готовий блок для `config.json`. Якщо система відома, але не підтримується (Workday, Personio, Teamtailor…), вона про це скаже, і я додам підтримку, якщо компанія тобі важлива.

**Підключено зараз:**
- **SoftServe** (`html`): читається перша сторінка списку `career.softserveinc.com/en-us/vacancies`. ⚠️ Я не знаю, чи список там відсортований за свіжістю і як працює пагінація, тому нові вакансії з другої сторінки бот не побачить. Також у списку вакансії всіх країн, а місто бот бачить не завжди, тож `requireLocation` вимкнено і відсікання йде за назвою.
- **Ajax Systems** (`ats`, Lever, `board: "ajax"`): токен я знайшла за посиланням на їхню вакансію в Lever, але саму стрічку відкрити не вдалося. Якщо токен чи система неправильні, бот через 8 запусків напише тобі про це в Telegram.
- **EPAM** не підключено: їхній сайт кар'єр я не змогла відкрити, а за описом він підвантажує список скриптом.

**Базова лінія.** Коли додаєш нове джерело (компанію, пошту, канал), його перший запуск лише запам'ятовує всі наявні вакансії і нічого не шле. Далі приходять тільки нові. Тож новий сайт на 150 вакансій не засипле чат.

**Про ввічливість.** Бот відкриває кожну сторінку раз на ~15 хвилин. Перед підключенням сайту глянь його `robots.txt` і умови використання. Для `ats`-API це не проблема: вони публічні й створені для цього.

## Підключення пошти (LinkedIn, Work.ua, Robota.ua, jobs.ua)

Це окремий крок. Без нього Djinni і DOU вже працюють.

**1. Окрема скринька.** Створи нову Gmail-адресу лише для алертів. Бот отримає доступ до неї, а не до твоєї основної пошти.

**2. Алерти на сайтах.** Зареєструйся на кожному сайті з цією адресою і створи підписку на пошук:
- **LinkedIn:** Jobs → пошук (наприклад, `full stack developer`, Ukraine або Remote) → увімкни **Set alert** → частота **Daily**. На безкоштовному акаунті до 10 алертів.
- **Work.ua, Robota.ua, jobs.ua:** на сторінці результатів пошуку шукай кнопку підписки на email (назва відрізняється).
- **Djinni** вже читається через RSS, окремий алерт не потрібен.

**3. Пароль додатка Gmail.** Для скриньки алертів увімкни двоетапну перевірку, потім у налаштуваннях акаунта Google створи **App Password** (16 символів). Звичайний пароль боту давати не треба, App Password можна будь-коли відкликати. Якщо вхід не проходить, перевір у налаштуваннях Gmail, що доступ по IMAP увімкнений.

**4. Секрети GitHub.** Додай:
- `IMAP_USER`: адреса скриньки алертів
- `IMAP_PASSWORD`: App Password
- `IMAP_HOST`: лише якщо не Gmail (за замовчуванням `imap.gmail.com`)

**5. Увімкни джерело.** У `config.json` в блоці `"name": "Пошта"` постав `"enabled": true`.

**Перевірка.** У лозі запуску (Actions → останній запуск) для кожного сайту буде рядок на кшталт `[LinkedIn] листів: 3, вакансій у них: 41`. Якщо листів більше нуля, а вакансій нуль, бот не розпізнав формат посилань у листі. У такому разі надішли мені вихідний код одного листа (в Gmail: ⋮ → «Показати оригінал»), прибравши особисті дані, і я підлаштую правило.

Бот лише читає скриньку: нічого не позначає прочитаним і не видаляє. Перший запуск після підключення пошти лише запам'ятовує вакансії з листів за останні 2 дні, а надсилає тільки ті, що прийдуть далі.

## Налаштування критеріїв

Усе в `config.json`:

| Поле | Що робить |
|---|---|
| `includeTitle` | У назві має бути хоча б одне з цих слів |
| `excludeTitle` | Якщо в назві є будь-яке з цих слів, вакансію пропускаємо (за замовчуванням senior, lead, java, php…) |
| `excludeText` | Те саме, але для назви й опису |
| `locations` | Слова для перевірки формату/міста (remote, Київ…) |
| `maxAgeHours` | Ігнорувати вакансії старіші за N годин |

Слова шукаються як цілі: `java` не збігається з `JavaScript`. Регістр не важливий.

У кожного джерела є свої перемикачі:
- `requireLocation: true` вимагає слово з `locations` у назві чи описі. Для Djinni вимкнено, бо в його стрічці місто часто не вказане, і з перемикачем ти б губила підходящі вакансії.
- `filterMode: "excludesOnly"` (для пошти) не вимагає слів з `includeTitle`, бо листи вже відфільтровані на самому сайті. Виключення (`senior`, `java`…) діють завжди.

### DOU: перевір адреси стрічок
Адреси `jobs.dou.ua/vacancies/feeds/?category=...` я підставив за зразком, але відкрити їх не вдалося. Відкрий їх у браузері: якщо бачиш XML зі списком вакансій, усе гаразд. Якщо ні, на сторінці вакансій DOU є посилання **RSS**: скопіюй адресу звідти в `config.json`. Якщо джерело не відповідає 8 запусків поспіль, бот напише тобі про це в Telegram.

### Telegram-канали
Бот читає публічні канали через веб-версію (`t.me/s/назва`). Приватні канали з посиланням-запрошенням `t.me/+...` так прочитати не можна.

**Підключено:** [Don't Panic Junior IT Jobs](https://t.me/Job_IT_Junior) (`Job_IT_Junior`, ~25 тис. підписників). Веб-версію відкрито, пости там це дайджести по 10-15 вакансій із прямими посиланнями на Djinni і DOU; бот розбиває їх на окремі вакансії. Канал орієнтований на джуніорів і майже весь контент дублює Djinni та DOU, тому дублі бот відсіює за посиланням. Приходитиме лише те, що пройшло твій фільтр за назвою.

**Не перевірено, але можуть бути корисні** (з добірок; веб-версію я не змогла відкрити): `jobforukrainians`, `univwork`, `internsgo`. Щоб додати, скопіюй блок каналу в `config.json`, зміни `name` і `channel`. Перед цим відкрий `t.me/s/<назва>` у браузері: якщо бачиш пости, канал підходить.

**Не підходять:** `nodejsjobsfeed` (переважно російськомовні вакансії російських компаній), `works_gamedev` (геймдев), `cryptoDevJobs` (крипто/блокчейн, хіба що ти шукаєш саме там).

Для одиночних постів назвою вакансії вважається перший рядок, посилання для кнопки береться з тексту посту (або веде на сам пост).

Щоб додати ще одне джерело, скопіюй будь-який блок у `sources` і змін `name` та `url`/`channel`. Для листів нового сайту додай правило в `rules` (`fromContains` і `linkPattern`, де перша група захоплення це id вакансії).

## Локально

```bash
npm install
npm test            # тести фільтрів, парсерів RSS, Telegram і листів
npm run dry-run     # показує, що б надіслалось, нічого не відправляє і не зберігає
TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=... npm start
```

## Обмеження

- GitHub Actions за розкладом може запускатися із запізненням на кілька хвилин, а інколи й більше.
- Якщо в репозиторії довго немає активності, GitHub може призупинити розклад. Оновлення `state/seen.json` ботом зазвичай це запобігає; якщо розклад зупинився, увімкни його знову у вкладці Actions.
- За раз надсилається максимум 20 вакансій, решта прийде наступного запуску.
- Розбір листів написаний за відомими форматами посилань і перевірений на синтетичних листах, а не на реальних. Перший реальний лист може знадобитися підлаштувати.
